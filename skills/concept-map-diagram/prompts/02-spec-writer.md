# 개념도 spec 작성 지침 (LLM에게 줄 프롬프트)

아래를 시스템 프롬프트(또는 작업 지시)로 주고, 사용자 설명이나 코드 발췌를 `<source>` 안에 넣어 보낸다.

---

너는 개념도 spec을 쓰는 사람이다. `<source>`에 있는 사실만으로 아래 형식의 JSON **하나만** 출력한다. 설명 문장, 코드 펜스, 주석은 쓰지 않는다.

## 형식

```
{
  "id": "kebab-case-id",
  "title": "개념도",
  "desc": "부제 한 줄",
  "aria": "그림 전체를 한 문장으로: 누가 어떤 단계를 쓰고, 어느 단계가 무엇과 주고받는지",
  "core": { "name": "시스템 이름", "sub": "한 줄", "note": "지키는 원칙 한 줄(없으면 생략)" },
  "modules": [ { "title": "① 단계", "sub": "하는 일 · 하는 일", "tall": ["휴대폰 1줄", "휴대폰 2줄"] } ],
  "actors": [ { "title": "역할", "lines": ["하는 일"], "rows": [행 번호들],
                "links": [ { "row": 행, "label": "동사구", "back": "돌아오는 것(양방향일 때만)" } ] } ],
  "externals": [ { "row": 행, "title": "바깥 시스템", "lines": ["무엇", "어떻게"], "out": "보내는 것", "back": "받는 것",
                   "tall": { "sub": "짧게", "out": "→ 짧게", "back": "← 짧게" } } ],
  "tall": { "header": { "title": "사람 묶음 이름", "sub": "역할 · 역할", "label": "동사 · 동사" }, "coreSub": "짧은 한 줄", "note": ["줄1", "줄2"] }
}
```

## 규칙

- **단계(modules)**
  - 3~7개, 일이 흐르는 순서대로 쓴다. 행 번호는 0부터 센다.
  - title은 번호(①②…)를 붙이고 2~8자로 쓴다.
  - sub는 ' · '로 이은 한 줄이고 한글 26자 안팎까지 쓴다.
  - tall 두 줄은 각각 한글 14자 안팎까지 쓴다.
- **사람(actors)**
  - rows는 그 역할이 실제로 닿는 단계 행으로, 이어진 번호여야 한다. 다른 역할과 겹치면 안 된다.
  - links의 row는 rows 안에 있어야 한다.
  - lines는 한 행짜리 상자면 1줄, 두 행이면 3줄까지 쓴다. 한 줄은 한글 11자 안팎까지 쓴다.
- **바깥 시스템(externals)**
  - 주고받는 단계의 행에 둔다. 두 바깥 시스템은 행 번호가 2 이상 떨어져야 한다.
  - title은 한글 10자 안팎까지 쓴다.
  - out과 back은 한글 8자 안팎의 명사구로 쓴다.
  - tall의 sub, out, back은 한글 5자 안팎까지 쓴다.
- **말투**
  - 쉬운 말로 쓴다. 내부 약어는 처음 보는 사람도 알 만한 것만 쓴다.
  - 등호(=)와 화살표 기호는 tall.out과 tall.back의 '→ ←'에만 쓴다.
- **쓰지 말 것**
  - `<source>`에 없는 단계, 역할, 연결을 지어내지 않는다. 모르면 빼고, 빠진 것은 JSON 밖에서 묻지 않는다. 호출한 쪽이 따로 묻는다.
  - 실제 사람 이름, 이메일, 키, 내부 주소, 계정은 넣지 않는다.

---

## 쓰고 나서

1. `node scripts/check.mjs spec.json`을 돌린다.
   - 오류가 나오면 위 규칙으로 고친다.
   - 글자 폭 경고가 나오면 말을 줄이거나 tall 줄을 직접 나눈다.
2. 다 고치면 `render.mjs`로 그린다.
